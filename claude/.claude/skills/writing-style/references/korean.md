# 한국어 산문 카탈로그

SKILL.md 한국어 레이어의 확장 카탈로그. 한국어 산문(PR 본문, 이슈, 설계 문서, README, Slack 초안)을
작성하거나 수정할 때 SKILL.md와 함께 읽는다. 규칙의 우선순위는 SKILL.md가 정하고, 이 파일은
세부 규칙과 예시를 담는다.

## 산문 다듬기

- **종결어미**: 개요, 배경, 목표처럼 독자가 먼저 읽는 산문은 해요체("~해요"). 실행 절차, 단계 목록, 체크리스트는 "~한다"체를 둬도 된다. 개요는 부드럽게, 절차는 건조하게. 해요체 산문 안에서는 어미를 "~해요"로만 고정하지 않고 "~죠", "~고요", "~거든요"를 가끔 섞어 리듬을 만든다. 짧은 반문("왜냐고요?")도 개요·배경에서 드물게 허용한다. 격식 등급 자체를 오가지는 않는다(해요체 문단에 "~한다" 문장을 섞지 않는다).
- **괄호 부연 최소화**: 흐름을 끊는 보충 괄호를 뺀다. 괄호를 남길 땐 그 값이 독자에게 무엇인지 알려주는 데만 쓰고, 내부 구현 메커니즘(파생 출처, 멱등성 같은 동작 내막)은 핵심이 아니면 통째로 뺀다. `prefix(KV) cache` → `prefix cache`, `라우터 변경 없이(round-robin 유지)` → `라우터 변경 없이`, `(Pipeline pkid에서 파생)` → `(PipelineJob의 mid)`, `terminal 전이 시(잡당 1회)` → `terminal 전이 시`. 괄호가 여러 개 쌓이면 가독성이 크게 떨어진다(2026-07-08 "괄호를 왜 자꾸 쓰냐" 지적). 파일 경로는 조사로, 부연은 수식·문장으로 푼다: `` `X`(models/a.py) 추가 `` → `` models/a.py에 `X` 추가 ``, `` `from_value`(파싱) `` → `` 파싱하는 `from_value` ``. 영어 병기 괄호는 첫 등장 1회만 쓰고 이후는 한글만 쓴다.
- **불릿은 한 항목 한 메시지**: 효과 설명 꼬리나 둘째 문장을 잘라 한 줄로 만든다. "이 문서를 정리한다" 같은 메타성 항목은 지운다.
- **영어 번역체를 우리말로**: 코드 식별자는 backtick으로 두되, "~을 만들다" 같은 직역 동사를 자연스러운 우리말로. `cross-pod 적중을 만들` → `Pod 간 prefix cache 적중률을 높일`.
- **담백하게**: 강조용 따옴표("…")로 힘주지 말고 평문으로 쓴다. 비유적 단어("함정")는 중립어("부분")로. 비유적 동사구도 직설 서술로 바꾸고, 통용 외래어는 유지한다: `코드가 움직이면 낡으니` → `코드가 변경되면 outdate되니`.
- **짧은 두 문장은 자연스럽게 잇는다**: `논의했어요. 하지만 ~` → `논의했지만, ~`.
- **문장 길이와 구조를 변주한다**: 같은 길이의 문장을 줄줄이 찍어내지 않는다. 단문만 이어지면 인접한 것을 연결어미로 묶어 복문과 섞고, 긴 문장 뒤에는 짧은 문장을 둔다. 균일한 리듬 자체가 AI 신호다(실측: 100자 이상 장문이 인간 글에 11배 더 많다).
- **제안은 권유형으로 맺는다**: 대안을 제시하는 문장은 "~하는 쪽이 좋겠어요"로 끝낸다. "쪽"을 주어 삼아 근거 명사구를 얹은 비교문은 어색하다: `~쪽이 진단 정보가 더 많아요` → `~쪽이 더 좋겠어요`.
- **참조는 텍스트가 아니라 링크**: 이슈 번호, 페이지명을 적을 때 실제 링크/멘션을 걸어 독자가 바로 이동하게 한다.
- **변경 목록은 명사형으로 맺는다**: PR Changes나 항목 나열의 종결을 "추가해요/제거해요" 대신 "추가/제거/변경/유지"로 잘라, 리뷰어가 변경사항만 훑고 코드 리뷰로 넘어가게 한다. 개요·배경 산문은 해요체를 유지한다. 제목 구실을 하는 자리 전부에 같은 규칙을 적용한다: 헤딩, 표 헤더, 불릿의 굵은 머리말, 단계 이름은 본문 문체와 무관하게 명사로 끝낸다(`무엇을 손보나요` → `교정 예시`, `시작하는 방법` → `시작 방법`).
- **여러 항목은 인라인 쉼표가 아니라 리스트로**: 셋 이상을 한 문장에 쉼표로 늘어놓지 않는다. 부모 불릿 아래 중첩 리스트로 세운다. `파싱 from_value, 판정 is_terminal, 변환 to_queue_status를 넣어요` → 부모 불릿 + 하위 3줄.
- **불필요한 주어를 뺀다**: 한국어는 주어 없이도 읽힌다. 문맥이 주어를 알려주면 뺀다. 번역체 주어를 반사적으로 넣지 않는다. "소비자"(consumer)처럼 코드 개념을 직역한 주어는 "호출부"로 바꾸거나 통째로 생략한다. `소비자가 도메인 enum으로 옮겨가 안 쓰이는 메서드 제거` → `안 쓰이게 된 메서드 제거`.

## AI스러움 패턴

한국어 LLM 출력에서 실측된 패턴. 초안에서 발견하면 그 문장을 재작성한다. 빈도 조건이 붙은
패턴은 그 빈도를 넘을 때만 고친다. 9번부터는 외부 카탈로그(KatFishNet ACL 2025,
DaleSeo/korean-skills, epoko77-ai/im-not-ai)와 대조해 업무 산문에 나타나는 것만 선별했다.

### 1. 연결어미 뒤 콤마 과다

한국어 LLM 텍스트에서 가장 강한 신호다(KatFishNet, ACL 2025). 연결어미(~고, ~며, ~지만, ~해서) 뒤에
반사적으로 콤마를 찍지 않는다. 콤마는 끊어 읽어야 할 곳에만 쓴다.

- `큐를 확인하고, 잡을 제출하고, 결과를 기다린다` → `큐를 확인하고 잡을 제출한 뒤 결과를 기다린다`
- `설정을 바꾸면, 서버가 재시작된다` → `설정을 바꾸면 서버가 재시작된다`

### 2. 중첩 hedging

추정 표현을 겹겹이 쌓지 않는다. 사실이면 단정하고, 불확실하면 조건이나 근거를 명시한 한 겹으로 줄인다.
불필요한 "~할 수 있습니다"도 같은 계열로 걷어낸다. 추측 종결(`~로 보인다`, `~인 듯하다`,
`~로 판단된다`)을 문장마다 붙이는 것도 마찬가지다.

- `성능이 개선될 수 있을 것으로 보입니다` → `성능이 개선돼요`
- `문제가 될 수도 있을 것 같아요` → `동시 요청이 100을 넘으면 문제가 돼요`

### 3. 형식명사 남용 (것/점/수/바)

형식명사로 문장을 명사화하지 않는다. 동사로 직접 서술한다.

- `주의할 점은 캐시가 무효화된다는 것이다` → `캐시가 무효화되니 주의한다`
- `개선의 여지가 있다는 점이 확인됐다` → `p95가 아직 2초라 더 줄일 수 있다`
- `핵심은 진입장벽이 낮다는 점에 있다` → `진입장벽이 낮다는 게 핵심이다`
- `~다는 뜻이다`, `~인 셈이다` 결말은 "~다"로 직접 맺는다. 문서 합산 2회 이하.

`~것이다` 종결 자체는 한국어 논설문의 일반 종결이다(실측: 인간이 LLM의 2배로 더 쓴다).
연속 3회 이상 반복될 때만 일부를 "~다"로 바꾼다.

### 4. 접속어 연발 (또한/따라서/즉/나아가)

문장마다 접속어로 시작하지 않는다. 논리가 이어지면 접속어 없이도 읽힌다.

- `또한 캐시를 지운다. 따라서 재시작이 필요하다.` → `캐시도 지우므로 재시작이 필요하다.`
- `즉, 이 값은 무시된다.` → `이 값은 무시된다.` `즉`은 문서당 2회 이하로 두고 `곧`, `말하자면`으로 바꾸거나 뺀다.
- 메타 진입(`이는 ~을 의미한다`, `이 점에서`, `이 말은`)은 삭제하고 본 서술로 바로 간다.

### 5. 기계적 나열 (첫째/둘째/셋째)

`첫째, ... 둘째, ... 셋째, ...` 대신 불릿을 쓰거나 문장으로 잇는다. 순서가 중요하면 마크다운
순서 목록(1. 2. 3.)을 쓴다. 문장 안 숫자 괄호 나열(`1) ... 2) ... 3) ...`)도 같은 계열이다.

- `첫째, 캐시를 지운다. 둘째, 서버를 재시작한다.` → `캐시를 지운 뒤 서버를 재시작한다.`
- `첫째 원인은 lock이고 둘째 원인은 timeout이다` → `원인은 lock과 timeout 두 가지다`

### 6. AI 관용구

`결론적으로`, `시사하는 바가 크다`, `주목할 만하다`, `~의 정수`, `~을 넘어서`. 결말 공식(`~할
때다`, `~할 시점이다`, `지금이야말로`)과 변환 공식(`X에서 Y로`, `X을 넘어 Y로` 슬로건)도 같은
계열이다. 거창한 도입(`오늘날 빠르게 변화하는 시대에`, `바야흐로`)도 빼고 바로 본론으로
들어간다. 삭제하거나 구체 사실로 바꾼다.

- `이 결과는 시사하는 바가 크다` → 삭제, 또는 `이 결과로 X 가설이 기각된다`
- `결론적으로 마이그레이션이 필요하다` → `따라서가 아니라 근거를 직접 잇는다: 스키마가 갈라져 마이그레이션이 필요하다`
- `'수동 운영'에서 '자동 운영'으로` 슬로건 → 무엇이 어떻게 바뀌는지 평서로 쓴다

### 7. 직역 개념어와 명사 압축

영어 개념어를 압축 한자어로 직역하면 번역체로 읽힌다. 자연스러운 구로 푼다(2026-07-03 스펙 리뷰에서 실측).

- 개념어 직역: `영어 산문 표면`(surface) → `영어 산문을 쓰는 범위`, `집행 장치`(enforcement) → `규칙 반영 체계`, `소비처`(consumer) → `참조하는 문서들`, `단일 정본`(canonical) → `원본 문서`, `준수율 처방`(prescription) → `수용률을 높이는 방법`, `업계 수렴`(convergence) → `업계 관행`
- 명사 압축(수식어를 살린다): `추상 규칙` → `추상적인 규칙`, `주기 재검증` → `주기적인 재검증`, `위반 패턴` → `규칙 위반 패턴`
- `~적 N` 추상 체인: `전략적 함의` → `전략 차원의 의미`, `실천적 기반` → `실천 토대`. 한 문서에 3회 이상 반복되면 풀어 쓴다. `-성`, `-화` 남발도 동사·형용사로 되돌린다(`효율화를 달성해요` → `효율을 높여요`)

### 8. 행동 압축어

영어 관용어나 한자어 분류어로 '행동'을 압축하지 않는다. 업계 표준 용어(fail-fast)라도 한국어
문장에서는 그 용어가 가리키는 행동을 그대로 쓴다(2026-07-07 PR #1746 리뷰 코멘트에서 실측,
사용자가 5건 직접 교정).

- `fail-loud하면 충분해요` → `ToolError를 던져 필터가 무시됐다는 사실을 호출자에게 바로 알리면 충분해요`
- `ENV 미설정 시 fail-fast가 필요해요` → `ENV가 없으면 초기에 바로 실패시키는 조치가 필요해요`
- `의도한 이연이면` → `의도한 거라면`
- `주석을 현행화하면` → `주석을 최신 사실에 맞게 고치면`
- `스모크 테스트를 권해요` → `테스트를 추가하면 좋겠어요` (분류어 없이 '테스트'로 충분)

코드 식별자나 인용(작성자가 쓴 용어를 되받을 때)은 예외다.

### 9. 번역투 조사

영어 전치사를 조사구로 직역한 형태. 동사에 직결하면 짧아지고 자연스러워진다.

- `~에 있어서`: 1회만 나와도 결정적. `운영에 있어서 중요한 것은` → `운영에서 중요한 것은`
- `~에 대해`: 목적격으로 직결한다. `이 문제에 대해 논의해요` → `이 문제를 논의해요`
- `~와 관련하여/관련된`: `보안과 관련하여 강화` → `보안을 강화`, `배포와 관련된 설정` → `배포 설정`
- `~에 기반하여/바탕으로`: `메트릭에 기반하여 판단` → `메트릭으로 판단`
- `~을 위해` 남발: `성능을 위해 도입` → `성능을 높이려고 도입`
- `~를 통해`: 한 문단 3회 이상 반복될 때만 `~로`, `~해서`로 분산한다. 개별 출현은 자연스럽다(실측: 비번역 한국어가 번역문보다 2배 더 쓴다).
- 이중 조사(`~에서의`, `~으로의`, `~로부터의`): 절로 푼다. `큐에서의 대기 시간` → `큐에서 기다리는 시간`

### 10. 영어식 피동과 잉여 동사

행위자가 있으면 행위자를 주어로 세운다.

- `가지고 있다`(have 직역): `강한 경쟁력을 가지고 있어요` → `경쟁력이 강해요`
- 이중 피동 `~되어진다`: 비문. `판단되어진다` → `판단된다`, 가능하면 능동으로. `쓰여진` → `쓰인`, `보여지는` → `보이는`도 같은 계열.
- `~에 의해`: `스케줄러에 의해 실행된다` → `스케줄러가 실행한다`
- `이루어지다/만들어지다`: `합의가 이루어졌어요` → `합의했어요`
- 잉여 진행형 `~고 있다`: 단순 시제로 충분하면 뺀다. `이 기능을 지원하고 있어요` → `이 기능을 지원해요`. 진행 중이라는 사실 자체가 정보일 때만 유지.

### 11. 추상 주어 + 만능 동사

사건·개념을 주어로 세우고 `가져오다/보여주다/제공하다/만들다`로 서술하는 영어식 통사.
구체 주어로 돌리거나 부사구로 푼다. 의인화(`기술이 묻는다`, `시대가 요구한다`)도 같은 계열이다.

- `이 변경은 성능 개선을 가져와요` → `이렇게 바꾸면 성능이 좋아져요`
- `이 지표는 병목을 보여줘요` → `이 지표를 보면 병목이 드러나요`

### 12. 영어식 잉여 표지 (-들, 해당, 대명사)

- 복수 `-들` 중복: 수량사나 수식어가 이미 복수를 알려주면 뺀다. `많은 사용자들이 기능들을 요청` → `많은 사용자가 기능을 요청`
- 지시관형사 `해당/본/동`: `이`로 바꾸거나 뺀다. `해당 기능` → `이 기능`, `본 문서` → `이 문서`
- 대명사 `그것은/이것은` 반복: 생략하고 바로 서술한다.

### 13. 균형 회피 어휘

`양쪽 모두 일리가 있다`, `장점도 있지만`, `신중하게 접근해야 한다`, `균형 잡힌` 같은 양면
제시로 판단을 피하지 않는다. 한쪽을 단언하거나 조건으로 가른다. 설계 문서와 리뷰 코멘트에서
특히 잦다.

- `두 방식 모두 장단점이 있어요` → `쓰기가 많으면 A, 읽기가 많으면 B가 나아요`

### 14. 대구 공식 연쇄

`A인가, B인가`, `A가 아니라 B`, `A라기보다 B` 평행구를 잇달아 쓰는 형태. SKILL.md 대조
부정문 금지의 변형들로, 부정 대구는 AI 대 인간 밀도 9.2배로 실측 최강 신호다. 연쇄 중 하나만
남기고 나머지는 직접 단언으로 바꾼다. 사실 정정 한 번(`원인은 lock이 아니라 timeout이에요`)은
예외다.

격상 틀도 같은 계열이다.

- `중요한 것은 ~이다` 틀은 직접 단언으로: `중요한 것은 순서예요` → `순서가 중요해요`
- `~뿐만 아니라 ~도` 연쇄는 평서 연결로: `빠를 뿐만 아니라 저렴해요` → `빠르고 저렴해요`

### 15. 동의어 이중 수식

`중요하고 핵심적인 역할`, `지속적이고 꾸준한 노력` → 수식어 하나만 남긴다.

### 16. 문장 군더더기 (김정선 계열)

없어도 뜻이 통하면 뺀다. 첨삭의 기본은 빼기다.

- `-의` 연쇄: `회사의 성장의 요인` → `회사가 성장한 요인`
- 군더더기 `있다`: `발표가 있을 예정이에요` → `발표할 예정이에요`, `벽에 걸려 있는 그림` → `벽에 걸린 그림`
- `-ㄹ 수 있는` 수식: 가능성이 요지가 아니면 뺀다. `성공할 수 있는 가능성` → `성공할 가능성`
- 에두름: `효과가 있다고 할 수 있어요` → `효과가 있어요`
- `~중 하나`(one of 직역): `가장 큰 문제 중 하나예요` → `손꼽히는 문제예요`
- 이중부정: `이 방식을 쓰지 않을 수 없어요` → `이 방식을 써야 해요`

### 17. 사동·시제·관사 직역

- `-시키다` 오용: 사동이 아니면 `-하다`. `성능을 개선시켰어요` → `성능을 개선했어요`. 진짜 사동(`모델을 학습시켰어요`)은 그대로 둔다.
- 시제 중복: `했었어야 했다` → `해야 했다`, `노력해 왔다` → `노력했다`, `지난주에 읽었던 책` → `지난주에 읽은 책`
- 관사 직역: `하나의 예시로` → `예시로`, `그 어떤 말도` → `어떤 말도`
- 안긴 절: `왜 실패했는가를 분석` → `왜 실패했는지 분석`

### 18. 일본어투·행정어

정해진 문구(법령, 계약)가 아니면 쉬운 말로 푼다.

- `~에 의거하여` → `~에 따라`
- `금번` → `이번`, `상기` → `위`, `익일` → `다음 날`
- `~에 위치하다` → `~에 있다`
- `~에도 불구하고` → `~지만`
- `~을 필요로 한다` → `~이 필요하다`
- `검토를 요한다` → `검토해야 한다`

## 리뷰 코멘트 톤 (PR 인라인 코멘트)

지적 내용은 유지하되 판정하는 서술을 제안형으로 바꾼다(2026-07-07 실측). 심사하는 어휘는
받는 사람이 방어적으로 읽는다.

- 단정 판정 → 완화 제안: `자동으로 켜는 게 일관돼요` → `자동으로 켜는 게 좀 더 일관성있어요`
- 훈수 동사 → 권유 어미: `테스트를 권해요` → `테스트를 추가하면 좋겠어요`. 코멘트 세트 전체에서 어미를 "~하면 좋겠어요"로 통일한다.
- 심사 어휘 → 인정 표현: `차단 자체는 여전히 유효하지만` → `차단 자체는 좋지만`. 작성자의 선택을 인정한 뒤 지적한다.
