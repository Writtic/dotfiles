# 한국어 산문 카탈로그

SKILL.md의 한국어 세부 규칙. 문장 성분과 조사, 어미 살리기, `~의` 남용, 비유 어휘, 한자어와 조사 결합은 fluent-korean이 정하니 여기 쓰지 않는다. 우선순위는 SKILL.md가 정한다.

## 문장

- **종결어미**: 개요, 배경, 목표는 해요체. 절차, 단계 목록, 체크리스트는 "~한다"체. 해요체 안에서 "~죠", "~고요", "~거든요"와 짧은 반문("왜냐고요?")을 가끔 섞어 리듬을 만든다. 한 문단 안에서 격식 등급을 오가지 않는다.
- **괄호 부연 최소화**: 괄호는 독자에게 그 값이 무엇인지 알려줄 때만 남긴다. `라우터 변경 없이(round-robin 유지)` → `라우터 변경 없이`. 파일 경로는 조사로, 부연은 수식으로 푼다: `` `X`(models/a.py) 추가 `` → `` models/a.py에 `X` 추가 ``. 영어 병기 괄호는 첫 등장 1회만.
- **문장 길이 변주**: 같은 길이 문장을 줄줄이 찍지 않는다. 단문이 이어지면 연결어미로 묶고(`논의했어요. 하지만 ~` → `논의했지만, ~`), 긴 문장 뒤에 짧은 문장을 둔다.
- **직역 주어는 뺀다**: 문맥이 주어를 알려주면 뺀다. `소비자가 도메인 enum으로 옮겨가 안 쓰이는 메서드 제거` → `안 쓰이게 된 메서드 제거`.
- **대상을 먼저 세우고 조건은 절로**: `넓힌 조회는 전체 스캔이 되니` → `조회 자체는 Range를 넓히면 전체 스캔이 되니`.
- **같은 대상은 같은 말로**: 처음 고른 말로 끝까지 간다.
- **군더더기 제거**: 정확해 보이려 붙인 한정어(`부분 실패로 기록` → `실패로 기록`)와 한 문장 안에서 겹치는 말을 지운다.
- **확인한 사실만**: 원인을 짐작해 나열하지 않는다. `권한이 없거나 API가 꺼진 리전 하나 때문에` → `API 에러가 발생한 리전 하나 때문에`.
- **강조 따옴표 금지**: 강조하려고 단어를 따옴표로 감싸지 않는다.

## 어휘

- **완곡한 동사 대신 실제로 한 일**: `정리했어요` → `구현했어요`, `에러로 보고` → `에러로 처리`, `다뤄서` → `파싱해서`, `합쳤어요` → `통일했어요`.
- **체감 대신 상태**: `문서에 안 보여요` → `문서에 명시되지 않았어요`, `URL에 남은 project` → `URL에 명시된 project`. 코드가 UI 상태를 바꾸면 피동이 자연스럽다(`select는 숨겨지는데`).
- **코드가 세는 동작은 `카운트하다`**: `같은 행이 다시 세져서` → `같은 행을 다시 카운트해서`.
- **운영 동사는 팀 용어로**: `기동` → `실행`, `재로드` → `리로드`, `정하는 값` → `세팅하는 값`. 방식을 채택한다는 뜻은 `~으로 가져가다`. 극존칭은 쓰지 않는다(`제안하신` → `제안해준`).
- **비용과 시간 비교**: `싸다`, `비싸다` 대신 `비용이 많이 나와요`, `비용이 저렴해요`, `시간이 적게/많이 걸려요`.
- **빌려 온 추상어 금지**: `회계`, `장부` → `사용량 집계`, `마지막 방어선` → `Redis가 직접 오래된 키를 지움`, `쓰기 예산` → `한 대가 쓸 수 있는 최대량`, `구멍` → `문제`. 추상 명사 대신 그 동작을 주어와 동사로 쓴다.
- **제안은 권유형**: `~쪽이 진단 정보가 더 많아요` → `~쪽이 더 좋겠어요`.
- **참조는 링크로**: 이슈 번호와 페이지명은 실제 링크나 멘션을 건다.

## PR 본문 구조

- **불릿은 한 항목 한 메시지**: 파급효과를 덧붙인 둘째 문장, "이 문서를 정리한다" 같은 메타 항목, 독자가 궁금해할 것 같아 미리 답한 문장을 지운다.
- **부모 불릿은 무엇을 바꿨는지 한 줄, 조건과 이유는 하위 불릿**: 셋 이상을 쉼표로 늘어놓거나 마침표로 둘째 문장을 잇지 않는다.
- **Changes는 명사형으로 맺는다**("추가/제거/변경/유지"). 목록이라 fluent-korean의 완결 문장 규칙 예외다. 헤딩, 표 헤더, 굵은 머리말, 단계 이름도 명사로 끝낸다(`시작하는 방법` → `시작 방법`).
- **Changes에 검증 결과를 쓰지 않는다**: `(전체 212개 통과)`와 별도 Validation 섹션을 넣지 않는다. `테스트 추가: A, B, C` 같은 콤마 체인도 금지.

## AI스러움 패턴

발견하면 재작성한다. 빈도 조건이 붙은 패턴은 그 빈도를 넘을 때만 고친다. 외부 카탈로그(KatFishNet ACL 2025, DaleSeo/korean-skills, epoko77-ai/im-not-ai, Turtle-Hwan/im-ai-copyeditor)에서 업무 산문에 나타나는 것만 골랐고, 충돌하면 측정 근거가 있는 쪽을 따른다.

- **연결어미 뒤 콤마 과다**: `큐를 확인하고, 잡을 제출하고, 결과를 기다린다` → `큐를 확인하고 잡을 제출한 뒤 결과를 기다린다`. 콤마를 빼면 드러나는 어색한 조사도 같이 고친다.
- **중첩 hedging**: 사실이면 단정하고, 불확실하면 조건이나 근거를 붙인 한 겹으로. `성능이 개선될 수 있을 것으로 보입니다` → `성능이 개선돼요`, `문제가 될 수도 있을 것 같아요` → `동시 요청이 100을 넘으면 문제가 돼요`.
- **형식명사 남용**: `주의할 점은 캐시가 무효화된다는 것이다` → `캐시가 무효화되니 주의한다`. `~다는 뜻이다`, `~인 셈이다`는 문서 합산 2회 이하, `~것이다` 종결은 연속 3회 이상일 때만 고친다.
- **접속어 연발**: `또한 캐시를 지운다. 따라서 재시작이 필요하다.` → `캐시도 지우므로 재시작이 필요하다.` `즉`은 문서당 2회 이하. 메타 진입(`이는 ~을 의미한다`, `이 점에서`)은 지운다.
- **기계적 나열**: `첫째/둘째/셋째`, 문장 안 `1) 2) 3)` 대신 불릿, 문장, 또는 번호 목록.
- **AI 관용구**: `결론적으로`, `시사하는 바가 크다`, `주목할 만하다`, `~을 넘어서`, 결말 공식(`~할 때다`, `~할 시점이다`, `지금이야말로`), 변환 슬로건(`X을 넘어 Y로`), 거창한 도입(`오늘날 빠르게 변화하는 시대에`). 지우거나 구체 사실로 바꾼다.
- **직역 개념어**: `집행 장치` → `규칙 반영 체계`, `단일 정본` → `원본 문서`, 직역 동사 `적중을 만들` → `적중률을 높일`. `~적 N` 체인(`전략적 함의`)은 문서에 3회 이상이면 풀고, `-성`, `-화` 남발은 동사로 되돌린다(`효율화를 달성해요` → `효율을 높여요`).
- **행동 압축어**: 업계 용어라도 그 용어가 가리키는 행동을 쓴다. 코드 식별자와 작성자 용어 인용은 예외.
  - `fail-fast가 필요해요` → `ENV가 없으면 초기에 바로 실패시키는 조치가 필요해요`
  - `의도한 이연이면` → `의도한 거라면`, `주석을 현행화하면` → `주석을 최신 사실에 맞게 고치면`, `스모크 테스트를 권해요` → `테스트를 추가하면 좋겠어요`
  - `테스트가 None 기대로 뒤집혔어요` → `assert가 []를 확인하다가 is None을 확인하도록 바뀌었어요`
  - `실측했어요` → 실제로 재었으면 `실제로 측정했어요`, 눈으로 봤으면 `직접 확인했어요`
  - `코드 블록을 접어` → `코드 블록을 자리 표시로 바꿔`
- **번역투 조사**: `~에 있어서`는 1회만 나와도 고친다(`운영에서`). `~에 대해`는 목적격으로(`이 문제를 논의해요`). `~와 관련하여`, `~에 기반하여`, `~을 위해` 남발은 직결한다. `~를 통해`는 한 문단 3회 이상일 때만 분산. 이중 조사(`~에서의`, `~으로의`, `~로부터의`)는 절로 푼다.
- **영어식 피동과 잉여 동사**: `가지고 있다` → `경쟁력이 강해요`, 이중 피동 `~되어진다`, `쓰여진`, `보여지는` 금지, `~에 의해 실행된다` → `~가 실행한다`, `합의가 이루어졌어요` → `합의했어요`, 잉여 진행형 `지원하고 있어요` → `지원해요`(진행 중이 정보일 때만 유지).
- **추상 주어와 만능 동사**: `이 변경은 성능 개선을 가져와요` → `이렇게 바꾸면 성능이 좋아져요`, `이 지표는 병목을 보여줘요` → `이 지표를 보면 병목이 드러나요`. 의인화(`시대가 요구한다`)도 같은 계열.
- **영어식 잉여 표지**: 수량이 이미 드러나면 `-들`을 뺀다. `해당`, `본`, `동`은 `이`로 바꾸거나 뺀다. `그것은/이것은` 반복은 생략한다.
- **균형 회피**: `두 방식 모두 장단점이 있어요` → `쓰기가 많으면 A, 읽기가 많으면 B가 나아요`.
- **대구 공식 연쇄**: `A인가, B인가`, `A라기보다 B`를 잇달아 쓰지 않는다. 격상 틀도 같은 계열: `중요한 것은 순서예요` → `순서가 중요해요`, `빠를 뿐만 아니라 저렴해요` → `빠르고 저렴해요`.
- **동의어 이중 수식**: `중요하고 핵심적인 역할` → 수식어 하나.
- **문장 군더더기**: `발표가 있을 예정이에요` → `발표할 예정이에요`, `성공할 수 있는 가능성` → `성공할 가능성`, `효과가 있다고 할 수 있어요` → `효과가 있어요`, `가장 큰 문제 중 하나예요` → `손꼽히는 문제예요`, `쓰지 않을 수 없어요` → `써야 해요`.
- **사동, 시제, 관사 직역**: `개선시켰어요` → `개선했어요`(진짜 사동은 유지), `했었어야 했다` → `해야 했다`, `하나의 예시로` → `예시로`, `왜 실패했는가를` → `왜 실패했는지`.
- **일본어투와 행정어**: `~에 의거하여` → `~에 따라`, `금번` → `이번`, `상기` → `위`, `~에 위치하다` → `~에 있다`, `~에도 불구하고` → `~지만`, `~을 필요로 한다` → `~이 필요하다`.
- **권고형 결말 남발**: `~해야 한다`, `~할 필요가 있다`가 문서에 5회 이상이면 주체를 둔 단언이나 조건문으로 바꾼다.

## 리뷰 코멘트 (인라인 코멘트와 답글)

기준은 johan의 인라인 코멘트 말투다. 짧고, 질문이 많고, 어미가 섞이고, 근거는 뒤에 한 절로 붙는다.

### 형태

- **짧게**: 한두 문장, 절반은 한 문장. `TypeVar가 안쓰이는 것 같아요.`, `주석과 코드 불일치`, `안쓰이네요.`
- **대안은 suggestion 블록에 한 줄 lead**: `요렇게 갈게요.`, `P5; Simplify`, `For debugging`.
- **반복 지적은 `ditto;`**, **낮은 우선순위는 `P5;`**로 시작한다. 약한 의견은 `약한 의견이라 넘어가셔도 됩니다!`, `취향이지만 한 번 남겨봐요.`처럼 밝힌다.
- **지시어는 `요거`, `요건`, `요기`, `여기도`**: `요거 어디서 주입되나요?`, `여긴 지우시죠!`
- **질문으로 짚는다**: `여기 도달 가능한가요?`, `~하신 이유가 있을까요?`, `의도하신걸까요?`, `~하면 어떨까요?`
- **근거는 뒤에 `~서요`로 한 절**: `요 변수 선언부도 좀 더 아래 선언해보는건 어떨까요? 선언부와 활용되는 부분이 멀면 가독성이 떨어져서요.`
- **어미는 섞는다**: `것 같아요`, `좋겠어요`, `좋겠네요`, `좋아보여요`, `필요해보여요`, `부탁드려요`, `해주세요`.
- **정리 요청은 `~하시죠`**: `argparse로 빼시죠`, `간단하게 이야기 나눠보시죠!`
- **가벼움 표시**(`ㅋㅋㅋ`, `ㅎㅎ`, `-!`, `~`)는 사소한 지적, 자기 실수, 농담에만. 버그와 데이터 손실에는 쓰지 않는다.
- **참조는 줄 앞뒤 링크**(`Ref:`, URL), 위치는 `L152`, `L261-L263`.
- **후속은 문장으로 가른다**: `다음 PR에서 고민해보죠!` 요약 코멘트에는 머지를 막는지 밝힌다.

### 내용

- **판정 대신 제안**: `일관돼요` → `좀 더 일관성있어요`, `테스트를 권해요` → `테스트를 추가하면 좋겠어요`. 작성자의 선택을 인정한 뒤 지적한다.
- **결과는 관측 가능한 증상으로**: "api key를 찾다 500이 나요", "실패 알림 지연이 4배가 돼요". 버그와 데이터 손실은 결과를 반드시 붙인다.
- **근거는 직접 확인한 것만, 확인 방법을 한 절로**: "이 파일을 지우고 돌려도 12개 테스트가 그대로 통과해서". 확인하지 않았으면 질문으로 남긴다.
- **동작과 PR 본문이 어긋나면** 어느 쪽이 의도인지 보고, 본문이 틀렸으면 description 수정을 요청한다.

### 답글

- 짧게: `네 맞아요!`, `반영 완료`, `수정했어요-!`. 커밋은 짧은 sha 링크로: `[c5e60ee](...)에서 삭제했어요.`
- 감탄 도입(`아하,`, `음,`, `오,`, `엇,`)은 답글에서만.
- 판단이 바뀌면 짧게 수용하고 끝낸다. 원래 지적을 변호하지 않는다.
- 동의와 한 일을 같이 쓰면 문두 동의를 뺀다: `맞아요. ~로 옮겼어요` → `~로 옮겼어요`.
- 받아들이지 않으면 판단 근거를 밝힌다.
- 오프라인 논의 결과는 `오프라인으로 이야기 나눴는데,` 또는 `구두논의:`로 남긴다.
- 논점이 셋을 넘으면 `Q1.`, `Q2.`로 나누고 대안을 묻는 형태로 맺는다.
- 프로세스 조언은 요약 코멘트에 둔다. `추가로 말씀드리고 싶은게 있는데요`로 열고 상대가 얻는 이득으로 맺는다.

## 갱신 규칙

실제 출력에서 새 패턴이 잡히면 추가하고, 더는 나타나지 않는 패턴은 지운다. 항목을 바꾸면 SKILL.md post-filter의 정규식도 같이 갱신한다. fluent-korean이 이미 정한 규칙은 추가하지 않는다. 교정 내력(날짜, PR 번호, 건수)은 적지 않는다.
